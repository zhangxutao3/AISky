# AISky 台风路径叠加方案

## 目标

在现有“风场流线”区域增加“台风路径”开关，同时显示：

1. AISky-Energy / AISky-SDS 从本地模式场识别出的路径；
2. 权威机构发布的实况与官方预报路径；
3. 所有时间按 UTC 保存，显示时统一跟随 AISky 的时区选择。

## 模式路径

模式路径不依赖外部台风网页。后台工作进程从每个预报时次的 SLP、10 米风场及可用热力场中：

- 在热带海域寻找闭合低压中心；
- 结合近中心风速、气压梯度和前一时次位置排除普通低压；
- 以最大移动距离约束连接连续中心；
- 输出经纬度、中心气压、最大近地面风速、预报时效和置信等级。

第一版以 SLP + WIND10 为核心，显示“模式识别路径”，明确区别于官方台风预报。

## 官方路径数据

- 中央气象台台风网提供实时台风展示，但当前未找到面向第三方应用、具有稳定版本承诺的正式公开 API 文档。
- 国家气象中心英文台风页面提供台风路径与强度产品入口，但页面同时声明站点资料的下载与再发布受授权限制。
- 日本气象厅提供公开的防灾信息 XML PULL 数据，包含北西太平洋台风位置和预报信息，可作为技术备用源，但界面必须标注为 JMA，不能显示为“中央气象台”。

因此，正式版建议先完成本地模式路径；中央气象台路径在取得书面使用许可或正式数据接口后接入。不要把未文档化的网页 JSONP 地址作为唯一生产数据源。

## 数据与缓存

- 标准化结构：台风编号、名称、发布机构、发布时间 UTC、路径点时间 UTC、经纬度、气压、风速、性质和预报/实况标记。
- 官方数据仅在开关开启时检查，建议 10–15 分钟缓存一次。
- 网络失败时继续显示带“缓存时间”的最近数据，不阻塞地图和本地预报。
- 缓存放入用户选择的 AISky 数据目录，随数据目录迁移。

## 地图交互

- “风场流线”下增加“台风路径”开关。
- 实况路径使用实线，官方预报使用虚线，Energy 与 SDS 使用两种清新的模型色。
- 路径点点击后显示 UTC/当前时区时间、中心气压、最大风速、来源和预报时效。
- 地图缩小时只显示路径和台风名，放大后显示时间点、强度节点与风圈。

## 建议实施顺序

1. 本地模式路径识别、缓存结构与地图图层；
2. 使用历史样本校验追踪稳定性；
3. 确认中央气象台数据授权或正式接口；
4. 接入官方路径、时区转换与离线缓存；
5. 增加路径误差对比和多模型一致性展示。
